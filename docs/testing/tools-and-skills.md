## 由易到难的判据

| 层次 | 验证问题 | 实际判据 |
|---|---|---|
| 基础加载 | 配置能否安全失败，权限是否扩大 | 默认关闭；缺失、重复、非法、超限拒绝；未知工具被交集排除；空权限禁止全部；迭代数只收紧 |
| 单会话 | 选择是否改变真正执行，失败是否可观测 | CLI 切换与回退；清空工作历史但保留事件；同批读取成功、写入拒绝；闭合会话及执行期间不能切换 |
| 模型与策略 | 文字能否越过运行时 | 伪造工具调用被拦；命令 denylist 保留；不支持工具的模型不调用 Provider；一次迭代上限确实停止 |
| Planner / Worker | 目录是否真正影响 Agent 选择 | 默认 Planner 端到端选择 skill.review；未知选择修复或回退；自定义未知名称及关闭功能后的旧 Skill 图返回失败且不调用模型 |
| 隔离与发布 | 能力是否绕过容器及独立验收 | 真实 Podman Worker 写入后读取当前容器内容；越权命令拒绝；验收通过才发布，失败保持真实 base 与 HEAD；容器与 worktree 清理 |

## 结果解释与剩余边界

固定 Provider 用于验证控制流，没有真实模型 API 费用。代码审查与补测试已提供可配置方法，但这里没有声称模型更容易找出缺陷或补出更好的测试。Skill 与普通定义的效果消融仍需另行准备自然任务、独立判据和新的数据/费用授权。

首次专项发现三处问题：事件检查同时计入了批次与逐调用记录；新历史应保留 system 消息；严格未知 Agent 异常逃出调度器。前两项调整测试口径，第三项改为无执行域的失败 Worker。另发现 CLI 的 list 保留名称与 Skill id 冲突，已加显式拒绝并重新冻结最终候选。独立 VM 首轮出现 python: not found，改用本地测试解释器的确切路径；容器命令仍使用受信镜像内的 python。还复现了关闭功能后旧 Skill 名称回退到更大权限的普通 Agent，改为始终保留 skill. 命名空间并拒绝未知名称。原始失败、取消及复验现场保留在私有验证目录。

Knowledge 尚未实现；MCP 的官方 SDK 互操作属于另一分支。本主题不把模拟 Provider、模拟沙箱或旧分支结果当作当前版本的真实验收。
